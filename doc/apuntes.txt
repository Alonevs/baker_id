Rol del Desarrollador: One-Man Army (Director, Diseñador de Interfaz, Programador y Usuario Final).Objetivo del Proyecto: Crear un emulador/motor de consola virtual de 32 bits (estilo Neo-Geo HD / Dreamcast 2D a 720p) y un IDE/SDK unificado de desarrollo visual con edición en tiempo real (Live Editing), sin scripts para el usuario final, programado íntegramente en Rust.Hardware de Destino Simulado: Arquitectura basada en el chip Allwinner D1-H (RISC-V RV64GCV) con 512 MB de RAM Límite.1. ARQUITECTURA GENERAL DEL BACKEND (100% RUST)El sistema se compone de dos hilos nativos principales (Multi-threading) que se ejecutan dentro del mismo ejecutable de PC, comunicados en vivo mediante canales de memoria compartida (std::sync::mpsc):Pilar A: El Emulador / Runtime (Bajo Nivel):Procesador: Intérprete del set de instrucciones RISC-V (RV64GCV).Gráficos: Renderizador 2.5D isométrico y por capas a 720p reales () a 60 FPS, utilizando la API gráfica wgpu o el crate pixels (aceleración por GPU nativa: Vulkan/DirectX).Audio: Mezclador por software multicanal utilizando rodio o cpal para reproducir pistas de fondo y efectos de sonido en formato .wav sin latencia.Gestión de Memoria: Mapeo estricto de un bloque de 512 MB de RAM virtual.Pilar B: El IDE / Entorno de Desarrollo (Interfaz Contextual):Interfaz Gráfica: Construida sobre egui o iced para obtener una aplicación de escritorio oscura, ultra ligera y de alto rendimiento nativo.Sistema de Nodos: Integración del crate egui_nodes para dibujar la lógica del flujo de la historia, cinemáticas y ramificaciones de misiones mediante cajitas y cables curvados en tiempo real.Base de Datos NARRATIVA: Gestión automatizada de archivos CSV estructurales mediante el motor de serialización serde + csv.2. EL LIENZO Y LA ESENCIA DE LOS "5 SEGUNDOS" (FLUJO DE TRABAJO)El entorno de desarrollo elimina las pestañas infinitas y los menús abstractos. Toda la programación del juego ocurre directamente haciendo Clic Derecho Contextual sobre el lienzo de juego.[ Clic Derecho en Sprite/Zona del Lienzo ]                   │                   ▼       [ Raycasting 2D en Rust ] ──► Detecta ID Única (GUID)                   │                   ▼  [ Despliega Editor de Nodos egui ] ──► Modifica Flujo/Texto/Ropa                   │                   ▼  [ Inyección Inversa Automática ] ──► Actualiza Fila Exacta en el CSVFlujo A: Interacción con NPCs y Línea de Tiempo Temporal (Time-Skip)Un mismo NPC puede existir en múltiples zonas o capítulos de la historia con ropas y diálogos diferentes. El IDE lo gestiona de un solo vistazo mediante la Ficha de Instancia Global:Cuerpo Base: Hoja de sprites nativa a 720p (Caminar, Quieto, Luchar, Dormir).Armario Dinámico (Capas de Ropa): Las ropas son hojas de sprites con fondo transparente que se dibujan exactamente encima del cuerpo base. El motor en Rust fusiona las texturas en la RAM al vuelo. No se redibuja el personaje entero para cambiarle de ropa.Inyección Directa al CSV: Al hacer clic derecho en el NPC y elegir la fase de la aventura actual, el usuario escribe el diálogo en la cajita flotante de texto. Al pulsar Intro, el IDE genera un ID único (NPC_Pueblo_Cap1_Fase2) y sobrescribe automáticamente esa línea exacta en el archivo CSV de fondo, sin que el usuario tenga que abrir bases de datos externas.Flujo B: Triggers y Cinemáticas de Zona (Estilo Adventure Forge)Si el jugador pisa una baldosa o zona específica y se activa una cinemática que no requiere un NPC físico (un terremoto, un texto del narrador, una cámara moviéndose sola):El usuario selecciona [Crear Zona de Evento] y dibuja un rectángulo invisible en el mapa.Clic derecho en el rectángulo ➔ Abre el Editor de Nodos Visuales.El nodo inicial generado automáticamente es [Al pisar Zona_X]. A partir de ahí, el usuario conecta con cables los nodos secuenciales: [Bloquear Mando] ➔ [Mover Cámara a X,Y] ➔ [Audio Play: sfx.wav] ➔ [Texto Narrador: "Frase..."] ➔ [Desbloquear Mando].3. ASSET PIPELINE: CREACIÓN AUTOMÁTICA DE SPRITES DESDE IMÁGENESEl motor incluye un backend compilador interno que procesa el arte del juego de forma transparente para el usuario:Importación Masiva: El desarrollador arrastra un archivo de imagen estándar (.png) en alta definición al IDE.El "Sprite Chopper" Automatizado: El IDE lee la imagen y, mediante menús guiados con previsualización en tiempo real, permite definir el tamaño de la rejilla (ej. ,  píxeles o resoluciones personalizadas para sprites gigantes HD).Compilador de Texturas Propietario: Rust procesa los píxeles de la imagen .png, elimina los metadatos pesados innecesarios y comprime la imagen en un formato binario puro optimizado para la GPU simulación de la consola virtual.Asignador de Estados Animados: Al importar el "Sprite Sheet", el IDE te permite etiquetar los fotogramas de forma visual: "Del fotograma 1 al 6 es 'Correr'; del 7 al 12 es 'Atacar'". Estas etiquetas se guardan como metadatos ligeros asociados al ID del personaje para que el editor de nodos los reconozca al instante.4. HOJA DE RUTA RELEVANTE PARA EMPEZAR A PROGRAMAR (PASO A PASO)Cuando se abra el entorno de desarrollo para picar las primeras líneas de código en Rust, se debe seguir este orden estricto de dependencias para garantizar la estabilidad del backend:[ ] FASE 1 (Los Datos): Programar las funciones nativas en Rust con serde y csv para leer, buscar filas específicas por ID, modificar cadenas de texto y guardar archivos CSV estructurales sin corromper el documento.[ ] FASE 2 (El Túnel): Crear la arquitectura multi-hilo en Rust utilizando canales mpsc. Conseguir que al cambiar un dato simulado en el hilo del editor, el hilo del emulador en marcha actualice su variable interna en milisegundos sin detener el bucle principal (Live Editing).[ ] FASE 3 (Los Nodos): Levantar la ventana de la interfaz gráfica con egui e integrar el lienzo de egui_nodes. Lograr que al escribir texto dentro de una cajita visual de nodo o al conectar un cable, se actualice automáticamente la fila del archivo CSV programada en la FASE 1.[ ] FASE 4 (La Pantalla HD): Inicializar la ventana de simulación a 720p usando wgpu o pixels. Cargar una hoja de sprites binaria y programar los algoritmos matemáticos base de Isometría y Z-Sorting automático (orden de dibujado por capas según coordenadas Y).[ ] FASE 5 (El Clic Contextual): Unificar el lienzo gráfico con la interfaz. Programar el algoritmo de colisión del ratón (Raycasting 2D) para que, al hacer clic derecho sobre un píxel que contenga un sprite, el IDE identifique su ID, abra su mapa de nodos y permita editar el flujo o el texto al instante en caliente.
